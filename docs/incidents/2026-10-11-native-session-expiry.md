# Native session invalidation after reauthentication

Production symptom reported on iPhone; Android appears unaffected and web has not been confirmed affected. Read-only checks found healthy API/web/database services and correct server time. Recent logs include successful provider authentication and /me validation followed by rejected realtime-ticket requests and device deregistration. Logs do not identify which client issued every request, so this correlation alone does not prove the whole incident's cause. Server-issued login tokens have a 24-hour lifetime; that policy is unchanged.

The client previously broadcast every HTTP 401 without its request identity. A delayed or retrying request using an older native bearer could therefore invalidate a newly authenticated session. The realtime client's disposal/generation check runs after the HTTP client's global broadcast, and cannot suppress that broadcast. Public login failures could also trigger global native invalidation.

The fix captures the original request bearer before transport changes, carries a private in-memory identity with the refusal, and only invalidates a matching active native session. Cookie-backed web invalidation retains existing behavior. The bearer is never added to diagnostic strings or logs. New authenticated sessions wait for any in-progress unauthorized-session cleanup before writing storage or registering push, preventing cleanup from erasing their credentials. Genuine current-session 401 responses continue to invalidate sessions.

Validation: 26 targeted HTTP/realtime/auth tests pass, including late old-bearer rejection, current-bearer rejection, failed public login and retained cookie behavior. Analysis passes. The full macOS suite passes 263 tests and fails four pre-existing home/overview pixel references (0.03–0.22% differences), unrelated to presentation changes in this patch; references and tolerance remain unchanged. Remote Linux CI and an actual newly distributed iPhone build must validate the patch before claiming production resolution. No production setting, token lifetime, deployment, signing or store delivery was changed.
